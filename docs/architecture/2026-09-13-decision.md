# Architecture: the decision page (2026-09-13, 05:20)

Igor asked for an architecture review from Codex (gpt-6-astra) and an independent one from a second Fable, "and
then we can decide if we want to refactor to it." Both are read-only reviews of main at 8fdf7d3 (Codex read the
`codex-bell` worktree, two commits older). Full texts: `2026-09-13-architecture-codex.md` (365 lines) and
`2026-09-13-architecture-fable.md`. This page is the comparison and my recommendation. One caveat on the
author: I wrote most of the file both reviews name as the strain, last night, so read the recommendation as
coming from the person who made the mess.

## Where they agree (so this is settled)

- **No rewrite.** `ExerciseCore` with `FrameRecord` as the boundary is the design paying for itself: every
  analyzer, detector and tracker change this week was decided by fixture numbers in a second. Keep the
  analyzers-per-exercise, the replay pipeline, the log-driven simulator checks, the bug-marker flow, stories as
  the spec, notes with the numbers, the small bridges (`CameraSource`, `FrameRecorder`, `VideoFile`,
  `WatchBridge`, `SessionLog`), the HDR rules in the views.
- **The one strain is `VideoPoseSession`**: 730 → 1,813 lines in 18 hours, 45 of 137 commits, nine jobs behind
  one main-actor class. Both say its size is a symptom; the disease is:
  1. the "what to do with a stored set" rule written four times (launch refresh, open, re-run from clip, analyze
     extracted) with drift: Auto re-detect needs ≥70 in two places and nothing in the third; #42 was this class.
  2. several async operations sharing the same current-set fields across awaits (`rerunExercise` set in one
     method, consumed in another; `refreshTask` and `analysisTask` guarded against each other in one direction).
  3. the app and posetrack each own an extraction loop (3ba7902 changed both) and there are four or five hand
     codecs for the same track JSON.
  4. nothing in `ExerciseAnalyzer/` has a host test; the stored-set decision, Recents and trim/undo are verified
     only by five simulator checks and the phone.
- **The next step is the same in both**: one pure, tested stored-set policy that open and launch refresh both
  call (Fable: `StoredSetPlan`; Codex: `RefreshPolicy`).

## Where they differ

| | Codex | Fable #2 |
|---|---|---|
| Destination | three layers: ExerciseCore / **ExerciseMedia** (new package: reader loop, pose adapter, detector, model readiness) / app | same modules; the session becomes a coordinator of four collaborators split along its own `// MARK:` lines |
| Data model | split `FrameRecord` into observations (raw) and `AnalysisResult` (derived); `restored` stops manufacturing a runnable engine | keep `FrameRecord`; one `TrackFile` codec, one held metric |
| Concurrency | every foreground operation gets an immutable request and an ID; late results are dropped by ID | one `OfflineJob` function used by the user pass, the refresh and the instrumented run; one `currentJob` with a priority flag |
| Steps | 6, first three 4–6 days, whole plan 10–16 | 9, steps 1–4 about a day, whole plan 2–3 days, stop after 4 is sound |
| Phone sessions | 2–3 | 1 (after the split, step 5) |
| Bugs found in passing | replay keeps the saved bell (**#49, real, fixed today**); `pull-tracks.sh` drops raw bell sightings (**#50**); `play()` runs after a cancelled pass; story 035's "missing clip opens from stored analysis" is not what `open` does; `justfile analyze` masks a build failure | `refreshTask` can interleave with a start-panel instrumented run (read from the guards, not reproduced); launch refresh decodes every stale track three times on the main actor |

Codex's review is the deeper read of the data model and it found the two bugs that matter to the lab (#49
explains why every tracker change of the night only reached the phone when the model name changed). Its plan
is sized for a team. Fable's plan is sized for this repo: each step is one commit on the cheapest rung that
sees it, and it names the line ranges.

## Recommendation

**Do Fable's steps 1–4 now, as four commits, no phone needed; take two of Codex's ideas into them; defer the
rest until the detector work is done.**

1. **`StoredSetPlan`** (pure, in ExerciseCore): stored version + model set, current ones, mode, stored exercise →
   `.keep` / `.replay(exercise, reason)` / `.rerunFromClip(exercise, reason)`. Replace the four sites. Write a
   test per today's behaviour first, then pick the Auto threshold once (**decision for Igor: 70 everywhere**,
   which is what open and refresh do; only the just-extracted path skips it and that is the one with no stored
   exercise to protect, so 70 changes nothing visible). This is Codex's `RefreshPolicy` too.
2. **Version and model set into `index.json`** with a one-time backfill; `isStale` and `models(for:)` stop
   decoding frames; `RecentsStore` gets a temp-directory host test. Codex's "one snapshot read per operation".
3. **`OfflineJob`**: the body of `rerunFromClip` and `analyzeAndPlay`/`finishAnalysis` as one function with
   `where`, the exercise and progress sinks; one `offline_pass` shape; `rerunExercise` deleted. Take Codex's
   operation identity here in its cheapest form: the job holds the entry id it will save to and a generation
   number; a finished job whose generation is stale saves nothing and plays nothing (that also fixes the
   play-after-cancel Codex saw). Not a request type per operation.
4. **`ModelSet`**: both models and plans behind `await ready()`; the three polling loops and `pendingLoadURL` go.

Then stop and measure: the four-way rule, the polling and the launch-refresh cost are gone, the app layer has
its first host tests, and nothing needed the phone. Step 5 (the split into `CameraRecorder`, `ClipEditor`,
`BugReporter`) is worth one gym session when Igor is next at the gym anyway. Codex's `ExerciseMedia` package
and the observation/result split are **deferred**: the shared extraction loop only pays once the pose adapters
converge, and that depends on whether the Ultralytics package builds for macOS (Fable's open question 1, not
checked by anyone). `FrameRecord` carrying both `bells` and `bell` is fine now that `analyze(frames:)` ignores
the stored `bell` (#49); the type split would be a 20-file change for a rule that is now one line.

**Cost.** Steps 1–4: about a day of agent time, host tests plus one `just test-sim` each. Step 5: a day plus a
gym session. Not before the bell work reaches Igor's gym: the 13-rep swing grades 28 % by eye today and the
detector cap is the lever under test (notebook H26); a refactor in the same window would make the fixture
comparisons ambiguous.
